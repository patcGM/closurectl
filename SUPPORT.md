# Support

## Security vulnerabilities

Do not open a public issue or attach real incident artifacts. Use the private
[GitHub security advisory form](https://github.com/patcGM/closurectl/security/advisories/new)
and follow [`SECURITY.md`](SECURITY.md).

## Bugs

Use the
[bug report form](https://github.com/patcGM/closurectl/issues/new?template=bug.yml)
with the exact closurectl version, operating system, Python or binary platform,
exit status, and a minimal synthetic reproduction. Remove credentials,
repository secrets, account IDs, private package names, and real incident data.

## Usage questions and feature requests

Use a
[support request](https://github.com/patcGM/closurectl/issues/new?template=support.yml)
for sanitized installation, compatibility, or workflow questions. The project
does not provide emergency incident-response services, recovery credentials,
provider account support, legal advice, or a guarantee of response time.

Provider outages and account recovery must be escalated to GitHub, npm, or AWS
through their own support channels.

Only releases and platforms listed in
[`docs/COMPATIBILITY.md`](docs/COMPATIBILITY.md) receive compatibility support.
